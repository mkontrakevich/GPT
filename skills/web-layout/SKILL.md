# Web Layout Skill — ARCH-grade rules

## Назначение
Единый стандарт верстки для сайтов и интерфейсов, где важны архитектурная точность, стабильная геометрия, чистая сетка и предсказуемое поведение при скролле. Правила собраны из требований проекта архитектурного бюро и дополнены production-проверками, выявленными на сайте ЦУМа.

## 1. Геометрия и сетка — обязательные правила
- Глобально: `box-sizing: border-box`; минимальная поддерживаемая ширина страницы — 320 px.
- Базовый модуль отступов — 8 px. Все интервалы по возможности кратны 8.
- Поля страницы задаются одним токеном и не размножаются локальными случайными значениями. Базовый диапазон: `clamp(18px, 3vw, 48px)`; для широких desktop-композиций допустимы увеличенные поля, если они одинаковы по всей странице.
- Одинаковые сущности выравниваются по одному шаблону. Заголовки однотипных страниц/секций не получают индивидуальных смещений.
- На desktop проектные карточки по умолчанию формируют строгую сетку; для архитектурного портфолио — 3 проекта по ширине.
- Вертикали, края карточек, заголовки и навигационные оси должны визуально совпадать. Никаких «почти одинаковых» отступов.

## 2. Header / sticky navigation
- Высота шапки — единый CSS token, например `--header-h`. Высота вторичной навигации — `--subnav-h`.
- Любой `top` у sticky/fixed элементов вычисляется только из этих токенов. Запрещено независимо прописывать `80px`, `68px` и т.п. в разных местах.
- Sticky/fixed элементы либо занимают место в потоке, либо являются осознанным overlay. Полу-overlay, случайные зазоры и пересечения запрещены.
- Header и вторичная navigation должны образовывать непрерывный chrome без полосы между ними при любом scroll position.
- У шапки всегда гарантирован читаемый контраст. Нельзя рассчитывать на то, что под прозрачной шапкой обязательно загрузится hero-image.
- Использовать ограниченную шкалу `z-index`, а не случайные значения.
- Для anchors задавать `scroll-padding-top` / `scroll-margin-top` с учетом полной высоты sticky chrome.

### Регрессионный тест ЦУМа
При прокрутке:
1. логотип и меню не меняют контраст на нечитаемый;
2. между header и editorial nav нет черной/белой щели;
3. editorial nav не перекрывает hero/content;
4. hero не прыгает при переходе header в scrolled state.

## 3. Изображения — NEVER STRETCH
- Фото никогда не растягивать.
- Базовая схема карточки: контейнер с `overflow: hidden`; изображение заполняет его через `width:100%; height:100%; object-fit:cover; object-position:center`.
- Пропорция медиа фиксируется заранее через `aspect-ratio` или заданную геометрию контейнера, чтобы исключить layout shift.
- Для архитектуры сохранять вертикали, геометрию и исходное визуальное DNA.
- Постоянные подписи под изображениями не добавлять без необходимости. В архитектурной сетке название проекта может появляться на hover.
- Production-страница не должна зависеть от случайных hotlink-картинок сторонних сайтов. Приоритет: локальный asset → официальный/владельческий CDN → контролируемый fallback.
- Каждая важная картинка имеет fallback. Ошибка загрузки не должна показывать browser broken-image icon или alt-текст поверх дизайна.
- Для `img` обязательно осмысленный `alt`, но визуальный fallback реализуется отдельно.

### ЦУМ: generated editorial media
- В production все редакционные фотографии ЦУМа загружаются только из локального `assets/generated/`.
- Запрещены hotlink-фотографии с новостных, туристических, архитектурных и иных сторонних сайтов.
- Источник визуального смысла — текст статьи; изображение автоматически генерируется через OpenRouter до публикации.
- Header logo не относится к AI imagery: используется отдельный брендовый SVG asset из `assets/brand/`.
- Изменение статьи не должно оставлять старую нерелевантную картинку: content hash обязан инициировать регенерацию.
- До успешной генерации новая HTML-ссылка на отсутствующий asset не публикуется.

## 4. Типографика
- Основной текст — нейтральный читаемый sans; для архитектурного проекта использовался Inter.
- Крупные акцентные заголовки могут использовать отдельную display-гарнитуру; ранее использовался Space Grotesk.
- Включать antialiasing и `text-rendering: optimizeLegibility`.
- Длина текстовой строки — ориентир 55–70 знаков.
- Межстрочный интервал основного текста — ориентир 1.35–1.5.
- Не применять микроскопический кегль для значимой информации. Контраст и размер проверяются без масштабирования браузера.

## 5. Viewport и overflow
- `overflow-x` не должен маскировать ошибку сетки. Горизонтального скролла в production быть не должно.
- `overflow:hidden` разрешен локально для media-crop/lightbox и на специально спроектированных one-screen страницах.
- Если страница по задаче должна помещаться в 1920×1080 без вертикального скролла, это задается как отдельный layout-mode, а не глобальное правило для всего сайта.
- Для viewport-height использовать `100svh` / `100dvh`, а не полагаться только на `100vh`.
- Для полноэкранных элементов учитывать `env(safe-area-inset-*)`.

## 6. Responsive
- Базовые контрольные диапазоны: desktop >1200, compact desktop/tablet <=1200, tablet <=900, mobile <=700 px.
- На mobile многоколоночная сетка становится одноколоночной.
- Горизонтальная editorial/menu navigation может скроллиться по оси X, но не должна ломать ширину страницы.
- Размеры header, subnav и их sticky offsets меняются через те же CSS variables.
- Проверять минимум: 1920, 1440, 1366, 1024, 768, 390 px.

## 7. Визуальная дисциплина
- Не усложнять интерфейс эффектами, если они не помогают навигации или пониманию.
- Hover: преимущественно opacity/background/color и контролируемая небольшая трансформация. Не ломать сетку на hover.
- Для архитектурной сетки допустима схема: белый фон + черное название на hover.
- Motion мягкий: reveal/parallax без тяжелого 3D и без скачков layout.
- Сохранять согласованность существующей системы 1:1: сетка, размеры карточек, размеры заголовков, меню, интервалы, padding, typography. Не «улучшать» отдельный экран ценой разрушения системы.

## 8. Структурные запреты
- Не использовать iframe для встраивания отдельных проектов/страниц. Проектные страницы самостоятельны и имеют понятный возврат в корень.
- Не создавать рекурсивные shell-layouts и дублирующие навигационные оболочки.
- Не прятать ошибки верстки через `overflow:hidden`, отрицательные margin или случайный `z-index`.

## 9. Production QA перед публикацией
Обязательная проверка:
- top / mid-scroll / bottom-scroll;
- zoom 80%, 90%, 100%, 125%;
- 1920 / 1440 / 1366 / 1024 / 768 / 390 px;
- нет horizontal scroll;
- нет overlaps, gaps, clipping, layout shift;
- все изображения загрузились или корректно ушли в fallback;
- нет broken-image icon / видимого alt поверх композиции;
- нет console errors;
- navigation links работают;
- header/subnav остаются геометрически стабильными;
- скриншоты top + mid-scroll + mobile просмотрены перед deploy.

## 10. Правило изменения существующего сайта
Сначала определить существующие tokens/grid/chrome/media rules. Затем менять компоненты через общие tokens. Локальный CSS override допускается только как временная диагностика; после подтверждения исправление переносится в системное правило.
